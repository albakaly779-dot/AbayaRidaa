# بوت رِداء لتأكيد طلبات العبايات

هذه خدمة مستقلة داخل مشروع رِداء، وتعمل على تيليجرام بنظام استقبال مستمر للرسائل. يبدأ العميل طلباً جديداً ثم يعبئ الاسم، رقم الهاتف، المحافظة، الموقع أو العنوان، رقم الموديل، والمقاسات، وبعد ذلك يرفع **صورة الإيداع** و**صورة الموديل**. قبل الإرسال تظهر له مراجعة نهائية مع أزرار التأكيد والتعديل والإلغاء.

عند التأكيد، يُحفظ الطلب في قاعدة SQLite محلية داخل مجلد البيانات، وتُحفظ الصور في مجلد خاص بصلاحيات مقيدة. كما يرسل البوت ملخص الطلب والصورتين إلى محادثات المسؤولين المحددة في `ADMIN_CHAT_IDS`.

> **تنبيه أمني مهم:** رمز البوت الذي أُرسل أثناء المحادثة يُعد سراً حساساً. لا تضعه في GitHub أو داخل الكود. أعد توليد الرمز من [BotFather](https://t.me/BotFather) إذا كان قد ظهر لأي شخص غير مخول، ثم ضع الرمز الجديد في ملف `.env` فقط.

## خطوات الإعداد

من داخل هذا المجلد انسخ نموذج الإعداد إلى ملف محلي:

```bash
cp .env.example .env
```

بعد ذلك افتح `.env` وضع رمز البوت الجديد في `TELEGRAM_BOT_TOKEN`. اترك `ADMIN_CHAT_IDS` فارغاً مؤقتاً إذا لم تعرف رقم محادثة المسؤول. شغّل البوت، افتح المحادثة معه، واضغط **معرفة رقم المحادثة**، ثم أوقفه وضع الرقم الناتج في `ADMIN_CHAT_IDS`. يمكن وضع أكثر من مسؤول بفصل الأرقام بفاصلة.

لا ترفع ملف `.env` أو محتويات `data/` إلى GitHub؛ قواعد الاستثناء موجودة في المستودع مسبقاً.

## تشغيل مباشر على Python

هذا الخيار مناسب للاختبار أو لجهاز يبقى متصلاً بالإنترنت طوال الوقت:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python bot.py
```

إذا أُغلق الجهاز أو انقطع الاتصال فلن يستقبل البوت الرسائل خلال فترة التوقف، لذلك يُفضّل الخادم الدائم للاستخدام التجاري.

## تشغيل Docker

هذا الخيار أسهل للتشغيل المستمر على خادم يدعم Docker، مع إبقاء قاعدة البيانات والصور في مجلد `data/` خارج الحاوية:

```bash
cp .env.example .env
# عدّل .env ثم شغّل:
docker compose up -d --build

docker compose logs -f
```

لإيقاف الخدمة دون حذف البيانات:

```bash
docker compose down
```

## مقارنة طرق التشغيل

| Approach | Tradeoffs | Cost | Setup Complexity |
|---|---|---|---|
| تشغيل مباشر على جهازك | لا يحتاج Docker، لكنه يتوقف عند إغلاق الجهاز أو انقطاع الإنترنت | لا توجد تكلفة برمجية إضافية؛ يعتمد على جهازك واتصاله | منخفضة |
| تشغيل Docker على خادم دائم | يعمل طوال الوقت مع إعادة تشغيل تلقائية ويحفظ الصور والطلبات في مجلد دائم | يعتمد على الخادم الذي تستخدمه | متوسطة |

الاختيار العملي لمتجر يستقبل طلبات يومية هو **Docker على خادم دائم**. أما التشغيل المباشر فيناسب اختبار المحادثة أولاً.

## تسلسل المحادثة

| المرحلة | البيانات المطلوبة |
|---|---|
| البداية | الاسم |
| التواصل | رقم الهاتف |
| العنوان | المحافظة ثم الموقع أو العنوان |
| المنتج | رقم الموديل ثم المقاسات |
| المرفقات | صورة الإيداع ثم صورة الموديل |
| المراجعة | تأكيد أو تعديل أو إلغاء |
| الإتمام | رقم طلب مثل `RD-260816-ABC123` وإشعار المسؤول |

يمكن للعميل كتابة `إلغاء` في أي وقت لإلغاء المسودة. إذا أُعيد تشغيل البوت أثناء تعبئة الطلب، تُستأنف المسودة من قاعدة البيانات المحلية بدلاً من فقدانها.

## متغيرات البيئة

| المتغير | الاستخدام |
|---|---|
| `TELEGRAM_BOT_TOKEN` | رمز البوت السري من BotFather، ويجب أن يبقى خارج Git |
| `ADMIN_CHAT_IDS` | أرقام محادثات المسؤولين الذين تصلهم الطلبات المؤكدة |
| `DATA_DIR` | مكان قاعدة البيانات والصور؛ يجب أن يكون على تخزين دائم |
| `POLL_TIMEOUT` | مدة انتظار استقبال الرسائل في كل طلب اتصال |
| `LOG_LEVEL` | مستوى السجلات، والقيمة الافتراضية `INFO` |

## ملاحظات الخصوصية والتشغيل

البيانات والصور التي يجمعها البوت قد تتضمن معلومات شخصية وإثباتات دفع. لذلك يجب تقييد صلاحيات الخادم ومجلد `data/`، وأخذ نسخة احتياطية مشفرة وفق سياسة المتجر، وعدم مشاركة قاعدة البيانات أو الصور في مستودع عام. لا يعتمد البوت على واجهة الموقع أو على متغيرات `VITE_`، فلا تُعرض مفاتيح الخادم للمتصفح.

يستخدم البوت **الاستقبال الطويل** من Telegram، وهو أسلوب مناسب لتشغيل الخدمة دون فتح منفذ عام على الخادم. توثيق Telegram الرسمي لطريقة استقبال التحديثات موجود في [Bot API — getUpdates](https://core.telegram.org/bots/api#getupdates)، وتوثيق إنشاء وإدارة الرموز موجود عبر [BotFather](https://core.telegram.org/bots#6-botfather).
